# Report-focused residual risks

The authoritative registers are `docs/technical-debt.md` and `docs/risk-register.md`. The relevant report findings are: unauthenticated HTTP Legacy segment and possible device spoofing; Cloud ML-KEM public-key substitution because no TLS/mTLS/pinning/signed distribution exists; Gateway compromise; ephemeral Cloud key plus in-memory session/sequence state; no cryptographic replay counter/window; no durable delivery queue; Python cannot guarantee zeroization; and fail-closed availability loss during Cloud/session failure. Existing controls are schema/sequence validation, AEAD, short 300-second sessions, bounded retries, SQLite uniqueness, metrics/logs, and failure tests. Those controls do not convert this prototype into a production-ready or highly available deployment.
